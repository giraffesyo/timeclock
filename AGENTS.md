# Pull requests

- Use descriptive branch names without agent or tool branding; do not add prefixes such as `codex/`.
- Every pull request that includes UI changes must include visual evidence of the resulting UI in its description: a screenshot, AVIF, GIF, video, or another suitable visual format.
- Capture the implemented changes and attach or embed the media so reviewers can view it directly from the PR. Use before-and-after captures when helpful, and include desktop and mobile views when the change affects both layouts.
- This repository is public. Screenshots and recordings show only Timeclock: its own app, or a neutral demo page. Never capture Parallel Works' internal applications (such as Within PW) or anyone's real data, even when a change was verified inside one; that evidence belongs in the internal repository's pull request.
- Don't name competitors in pull requests, commits, branch names or comments, even as design inspiration; describe the design on its own terms. Naming an integration Timeclock actually has, such as Toggl, is fine.
