# Pull requests

- Use descriptive branch names without agent or tool branding; do not add prefixes such as `codex/`.
- Every pull request that includes UI changes must include visual evidence of the resulting UI in its description: a screenshot, AVIF, GIF, video, or another suitable visual format.
- Capture the implemented changes and attach or embed the media so reviewers can view it directly from the PR. Use before-and-after captures when helpful, and include desktop and mobile views when the change affects both layouts.
- This repository is public. Screenshots and recordings show only Timeclock: its own app, or a neutral demo page. Never capture other applications, including ones that embed Timeclock, or real people's data; verify there if you must, but that evidence belongs in that application's own repository.
- Don't mention other projects or products in pull requests, commits, branch names or comments; describe each change on its own terms. The one exception is a public product Timeclock has a first-party integration with, where the change is about that integration.
